## 不影响当前 REJECT 的限制

1. 合同第55行同时写“每折系数必须为正”和“正折至少75%”，文字上有 100% 与 75% 的歧义。本次只有 1/8 为正，按任何一种解释都失败；若未来复用，应在新合同中只保留一个标准。
2. 代码用“每年样本至少40行”识别完整年度，而不是硬编码 2018–2024。本次 2025 只有6行，所以当前结果完全符合合同；若以后重跑，2025达到40行后会偏离这份一次性合同。
3. 脚本只在运行前 assert 合同 SHA，没有同时 assert 输入 SHA；不过该输入的 `4202f0...` 已在本挑战前的 crowding source-manifest v2 和最终独立审计中冻结，本次 manifest 仍是同一 SHA，因此当前绑定成立。
4. manifest 没记录运行命令、Python/依赖版本、缺陷日志、旧 `.pyc` 或上游 raw→diagnostic 的完整链。它足以绑定本分支的核心输入、合同、代码和结果，但不是自包含的长期复现包。
5. 结果 Markdown 只展示摘要，未列出 I 系数方向、leave-one 最差值、severe gain 等全部 gate；JSON 才是完整决定记录。摘要没有写错，但人工只看 Markdown 时不够透明。
6. 本审计没有重新审核上游五个免费数据源的经济定义或 current-vintage 限制；这些属于已经冻结的输入质量限制。当前挑战仍是 post-hoc pseudo-OOS，不能转成交易或生产结论。

以上限制都不会把本次 `INTERACTION_REJECT` 翻成 PASS；没有 `REJECT_WITH_DEFECT` 级问题。
